    ```java
    // ── Key-Value ──

    /**
     * Durably stores {@code value} under {@code key} in this view's tag-scoped
     * key-value store. Overwrites any existing value.
     */
    CompletableFuture<Void> setValue(String key, byte[] value);

    /**
     * Returns the stored value for {@code key}, or {@code null} if absent.
     */
    CompletableFuture<byte[]> getValue(String key);

    /**
     * Removes the stored value for {@code key}. No-op if absent.

    ```

    Note: These are abstract (non-default) methods on the interface — DefaultLogView must implement them.

    **DefaultLogView.java** — add implementations after `subscribeTail`:

    ```java
    @Override
    public CompletableFuture<Void> setValue(String key, byte[] value) {
        return CompletableFuture.runAsync(() -> {
            try {
                service.adapter().setTagValue(tag, key, value);
            } catch (IOException e) {
                throw new SharedLogService.LogReadException("setValue failed for tag=" + tag + " key=" + key, e);
            }
        });
    }

    @Override
    public CompletableFuture<byte[]> getValue(String key) {
        return CompletableFuture.supplyAsync(() -> {
            try {
                return service.adapter().getTagValue(tag, key);
            } catch (IOException e) {
                throw new SharedLogService.LogReadException("getValue failed for tag=" + tag + " key=" + key, e);
            }
        });
    }

    @Override
    public CompletableFuture<Void> deleteValue(String key) {
        return CompletableFuture.runAsync(() -> {
            try {
                service.adapter().deleteTagValue(tag, key);
            } catch (IOException e) {
                throw new SharedLogService.LogReadException("deleteValue failed for tag=" + tag + " key=" + key, e);
            }
        });
    }
    ```

    Check what `CompletableFuture` imports are already present in DefaultLogView — add only if missing.
    Check what executor `CompletableFuture.runAsync/supplyAsync` uses — the common pool is fine for now.

    ```java
        assertThatThrownBy(() -> view.getValue("ck").join())

        assertThatThrownBy(() -> view.deleteValue("ck").join())
            .hasCauseInstanceOf(UnsupportedOperationException.class);
    }
    ```

    Use `assertThatThrownBy` from AssertJ — already used in the codebase. The `CompletableFuture.join()` wraps exceptions in `CompletionException`; `hasCauseInstanceOf` unwraps the cause.

    IMPORTANT: Read the test file first to verify:
    - `ORDERS` constant name
    - Whether `assertThatThrownBy` is already imported
    - What `SharedLogService.LogReadException` wraps — the DefaultLogView wraps IOException in LogReadException; LogReadException extends RuntimeException, so CompletableFuture wraps it in CompletionException. The cause of CompletionException is LogReadException; the cause of THAT is UnsupportedOperationException. Use `getRootCause().isInstanceOf(UnsupportedOperationException.class)` if `hasCauseInstanceOf` doesn't chain deep enough.

    Actually, verify the exact exception chain:
    - `UnsupportedOperationException` is thrown by adapter default
    - `DefaultLogView` catches `IOException` only — `UnsupportedOperationException` is a `RuntimeException`, it will NOT be caught by the `catch (IOException e)` block
    - It will propagate directly, wrapped in `CompletionException` by `CompletableFuture`
    - So `hasCauseInstanceOf(UnsupportedOperationException.class)` is correct

    If `assertThatThrownBy` is not imported, add: `import static org.assertj.core.api.Assertions.assertThatThrownBy;`
